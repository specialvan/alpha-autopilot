# V8.2 执行清单

> 用途：
> 这不是解释性计划，而是后续实现必须照着拆的执行清单。
>
> 原则：
> 先锁 schema 和边界，再锁 constraints 和 selector，再补 transition 状态机，最后才收 controller。

## 0. 执行前提

在进入任何代码整改前，必须先承认下面三个现实：

1. `backend/app/services/narrative_v8/` 已经有部分 runtime，不是从零开始
2. 现有 runtime 已经覆盖了 schema / selection / flavor / ledger / controller 的一部分能力
3. `transitions.py`、`TransitionLayer`、`current_control_state`、`packet.transition` 与 controller 去规则化主收口已经落地，当前剩余的是边界守门与残余风险审计

因此后续执行不是“新建整个 v8”，而是“在现有 v8 runtime 上做 V8.2 对齐整改”。

后续实施必须按下列顺序推进，不得跳步：

1. `PR-1 Schema 与边界锁定`
2. `PR-2 Constraint 与 Selector 硬过滤闭口`
3. `PR-3 Flavor、Ledger 与 Transition State Machine 对齐`

5. `PR-5 整体验证与送审门`

## 8. 一句话执行原则

`V8.2` 的执行顺序不是：

“先把 controller 拼出来，再慢慢补规则。”

而必须是：

“先把 schema、constraints、validation、transition state machine 这些硬边界锁死，再让 controller 变成一个不需要发明规则的编排层。”
