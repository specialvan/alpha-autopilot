# 任务发起模板

把新需求直接按下面格式填写，方便快速判定层级和执行方式。

## 1. 任务信息

- 任务名称（必填）
- 提出背景（必填）
- 目标结果（必填）
- 优先级（必填：高 / 中 / 低）
- 期望完成时间（必填）
- 责任人（必填）
- 相关方（必填）

## 2. 层级判断

- [ ] Baseline
- [ ] Increment
- [ ] Experimental

### 判定理由

说明为什么属于这一层：

- 是否影响 `v1/v2` 基线
- 是否属于 `v3` 增量
- 是否只是实验性验证
- 是否会改变主线默认行为

## 3. 影响范围

### 代码

- 需要修改哪些文件 / 模块（必填）
- 是否新增模块
- 是否影响接口
- 是否影响数据结构
- 是否影响前端

### 文档

- 需要更新哪些文档（必填）
- 是否要更新总纲
- 是否要更新状态文档
- 是否要更新任务文档
- 是否要更新归档索引

### 测试

- 需要补哪些单元测试
- 需要补哪些集成测试
- 需要补哪些回归测试
- 需要补哪些验收测试

## 4. 设计边界

### 允许做的事

- 本次任务明确允许的内容

### 不允许做的事

- 本次任务明确禁止扩展的内容

### 回滚方式

- 关闭方式
- 回退方式
- 恢复方式

## 5. 执行要求

- 是否只做一个目标（必填：是 / 否）
- 是否先补测试（必填：是 / 否）
- 是否先更新文档（必填：是 / 否）
- 是否需要灰度或开关（必填：是 / 否）
- 是否需要归档旧口径（必填：是 / 否）

## 6. 验收标准

### 功能验收

- 需求完成后必须满足的量化结果
- 需要验证的指标和阈值

### 稳定性验收

- 旧功能不能被破坏
- 默认路径不能异常
- 回滚后必须恢复正常

### 文档验收

- 对应文档已更新
- 主线文档与状态文档一致
- 回滚与门禁说明已补齐

## 7. 结论

- 是否进入开发（必填：是 / 否）
- 是否需要先补测试（必填：是 / 否）
- 是否需要先更新文档（必填：是 / 否）
- 是否需要执行治理升级（必填：是 / 否）
- 是否需要重收敛旧口径（必填：是 / 否）

## 8. 一句话原则

> 先填模板，再判层级；先定边界，再做执行；先补测试，再更新文档。
