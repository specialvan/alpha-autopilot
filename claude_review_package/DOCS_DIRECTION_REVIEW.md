# 文档方向一致性评审

## 结论

整体来看，项目中的开发需求、路线图、进度、阶段任务、前端/后端 PRD 之间**没有明显方向漂移**。主线一直保持一致：

- 从小说章节推荐原型出发
- 逐步补齐状态建模、特征矩阵、训练反馈闭环
- 再扩展到 `v2` 工作台与 `v3` 逆向拆解质量层
- 最终目标仍然是“可解释、可迭代、可验证、可进化”的章节规划系统

当前文档体系更像是**同一主线的分阶段展开**，不是多条并行产品线互相打架。

## 一致性检查结果

### 1. 总目标一致

`README.md`、`MASTER_ROADMAP.md`、`PROJECT_STATUS.md` 的总目标都一致指向：

- 小说章节推荐
- 写作辅助
- 可解释推荐
- 训练与反馈闭环
- 工程化可迭代

这说明项目没有从“写作辅助系统”偏移到别的无关方向。

### 2. 阶段划分一致

各文档对阶段的描述虽然表述略有不同，但核心逻辑一致：

- 第一阶段：原型闭环
- 第二阶段：稳定化与扩展
- 第三阶段：价值进化 / 质量层接入

`THIRD_PHASE_ROADMAP.md` 只是把第三阶段进一步细化为 `V3 Reverse Decomposition Quality Layer` 和训练链路接入，并没有改变总路线。

### 3. `v2` / `v3` 的关系一致

从文档看，`v2` 和 `v3` 没有被写成两个互相独立的产品，而是：

- `v2` 负责推荐工作台、核心交互与主链路
- `v3` 负责质量层、逆向拆解、QC 和训练前过滤

这个分工是合理的，也和 `PROJECT_STATUS.md` 中“`v3` 尚未正式接入主训练链路”的描述一致。

### 4. 风险描述一致

几个文档都重复提到相同风险：

- `mapped_chapter` 还不是完整真实章节 API
- `V3` 目前是启发式 prototype
- `matrix_projection` 尚未正式进入训练主循环
- 前端 dashboard 仍带原型性

这些风险前后一致，没有出现“某个文档说已生产化，另一个文档说还在原型”的冲突。

## 轻微漂移风险

虽然没有明显漂移，但有几个需要持续盯住的点。

### 1. 文档数量较多，容易造成“局部表述膨胀”

现在有很多阶段性文档、评审文档、任务文档、交付文档。它们都在描述同一件事，但措辞层层叠加后，容易让人误以为项目已经进入更成熟阶段。

风险不是方向变了，而是**表达层级过多导致外部误判成熟度**。

### 2. `v3` 很容易被误解为新主线

`v3` 在文档里被描述得很完整，包含 taxonomy、schema、decomposition、checkpoint、admission、QC、训练接入。这个完整度很高，容易让人产生“主项目正在转向质量层产品”的感觉。

实际从 `PROJECT_STATUS.md` 和 `THIRD_PHASE_ROADMAP.md` 看，`v3` 仍然应该是主推荐链路的增强模块，而不是替代主线。

### 3. 前端文档与后端文档的粒度不完全一致

`frontend_PRD.md` / `frontend_PROJECT_STATUS.md` 和后端文档之间，阶段描述粒度不完全相同。虽然不冲突，但如果未来继续扩展，建议把统一的总路线图作为唯一源头，其他文档只做局部展开。

## 方向是否漂移

### 结论

**没有明显漂移。**

更准确地说，当前是“主线清晰、分支较多、表达较繁”的状态，不是“方向混乱”。

## 建议的收敛动作

### 1. 设一个唯一总纲文档

建议把 `MASTER_ROADMAP.md` 作为唯一方向总纲，其他文档都标注引用它，避免每份文档都重新定义一次阶段。

### 2. 明确 `v2` 与 `v3` 的关系

建议在总纲里固定一句话：

- `v2` 是主推荐工作台与交互链路
- `v3` 是质量层与训练增强模块
- `v3` 不替代 `v2`，而是为 `v2` 提供质量与解释增强

### 3. 给所有阶段文档加一个统一状态标记

每份需求、路线图、进度文档最好都加：

- 当前所处阶段
- 是否已接入主链路
- 是否仍为实验模块
- 是否可用于生产判断

### 4. 收敛临时产物命名

建议把以下内容分层管理：

- `roadmap`：路线图
- `status`：真实进度
- `plan`：实施计划
- `review`：评审意见
- `tasks`：执行任务

这样能减少同类文档互相覆盖的风险。

## 最终判断

项目开发方向当前是稳定的，核心主线没有漂移。接下来最重要的不是重新定义目标，而是：

- 收敛文档表述
- 强化总纲约束
- 防止 `v3` 被误写成独立新产品
- 让进度文档持续与真实实现同步
