# 给 Codex 的评审开发任务说明

## 任务名称

V3 读者留存目标函数与生成控制层升级

## 任务背景

`v1/v2` 已经完成稳定闭环与工作台收口，但最初立项时并没有把“留住读者”抽象成顶层目标函数。当前系统的风险是：

- 结构正确，但可能不够抓人
- 标签很多，但可能只是描述项
- 生成结果可能偏模板化、偏八股文
- 核心目标可能停留在“写得完整”，而不是“继续想读”

因此需要在 `V3` 中追加：

1. 读者留存目标函数
2. 生成控制层
3. 标签到决策的映射
4. 留存导向的评估与反馈闭环

## 任务目标

请围绕以下目标进行评审与开发：

- 在不破坏 `v1/v2` 基线的前提下，为项目追加顶层“留存优先”目标函数
- 将情绪、节奏、爽点、悬念、冲突、钩子等标签从描述字段升级为决策变量
- 定义生成控制层，让这些标签真正影响章节规划、候选排序和生成建议
- 保留现有结构化能力，不把项目改成纯模板或纯八股规则引擎
- 让系统更能生成“吸引读者继续读下去”的内容

## 归属层判断

### 归属层

- [ ] Baseline
- [x] Increment
- [ ] Experimental

### 判断依据

- 这是在 `v1/v2` 基础上的增量目标函数追加，不是替换基线
- 它会影响推荐/生成策略、评估体系和反馈闭环，属于 `V3`
- 它不是试验性探索，而是明确的阶段性目标升级
- 它不会改变 `v1/v2` 默认稳定路径，但会为 `V3` 增加上层控制能力

## 需要 Codex 评审的重点

### 1. 目标函数是否定义清楚

请确认：

- 是否已经把“留住读者”定义成系统顶层目标
- 是否能拆出可控子维度，例如：
  - 情绪推进
  - 节奏推进
  - 爽点密度
  - 悬念保持
  - 冲突增长
  - 角色吸引
  - 章节钩子
  - 信息释放节奏

### 2. 生成控制层是否合理

请确认：

- 是否存在明确的生成前控制输入
- 是否存在明确的控制层输出建议
- 标签是否真正影响生成决策，而不是只用于展示
- 是否保留结构约束，避免变成纯模板化输出

### 3. 标签体系是否需要重定义

请确认：

- 情绪、节奏、爽点、悬念、冲突、钩子等标签
  是否应从“描述项”升级为“决策变量”
- 是否存在标签权重、动态调权、题材/阶段差异化配置的必要性

### 4. 评估与反馈是否要改

请确认：

- 是否需要加入留存代理指标
- 是否需要加入章节吸引力评分
- 是否需要加入“继续阅读意愿”导向的代理评价
- 是否需要把反馈回写到标签权重与控制策略中

## 设计边界

### 允许做的事

- 追加 `V3` 留存目标函数
- 建立生成控制层
- 重定义标签作用
- 增加留存导向评估维度
- 逐步接入工作台与训练链路

### 不允许做的事

- 不允许推翻 `v1/v2` 基线
- 不允许把项目改成纯模板生成器
- 不允许删除结构约束
- 不允许把实验性方案直接写成默认主线
- 不允许让新目标函数误伤现有稳定路径

## 回滚策略

- `V3` 留存控制层应可单独关闭或降级
- `v1/v2` 默认路径必须保持可运行
- 任何新增标签权重逻辑都应保留回退到基础版本的能力
- 任何反馈回写都应可暂停，不得阻断主线

## 验收标准

### 功能验收

- 能把“留住读者”作为显式目标
- 能让情绪/节奏/爽点等标签真正参与生成控制
- 能输出更偏吸引力的章节建议
- 能避免明显模板化、八股文式输出

### 稳定性验收

- `v1/v2` 默认路径不受影响
- 新控制层可回退、可关闭、可降级
- 结构约束仍然存在，不会失控

### 文档验收

- `V3` 路线图和任务文档已更新
- 项目状态已同步
- Codex 评审入口已同步

## 给 Codex 的执行要求

1. 先阅读治理规范和 `README_FOR_CODEX.md`
2. 再阅读本任务说明与 `V3_READER_RETENTION_SPEC.md`
3. 明确这是 `Increment` 层任务，不是 Baseline 重写
4. 先做目标函数和控制层设计，再做实现
5. 先补测试，再改代码
6. 完成后同步状态和路线图
7. 保留 `v1/v2` 可回滚能力

> 这次不是做“更会套结构”的小说辅助，而是给 `V3` 追加“留住读者”的顶层目标函数和生成控制层，让情绪、节奏、爽点等标签真正影响生成决策。
