# 新需求接入到执行的一页式流程

## 1. 提需求

用户或项目方提出一个新需求，先记录：
- 需求名称
- 目标
- 原因
- 期望结果
- 优先级

## 2. 填模板

把需求填入 `new_requirement_intake_template.md`，完成：
- 层级判断
- 影响面分析
- 设计边界
- 回滚策略
- 验收标准

## 3. 判层级

判断该需求属于：
- `Baseline`
- `Increment`
- `Experimental`

### 规则
- 改变主线默认行为的，先不要直接进主线
- 新能力默认进入 `Increment`
- 不确定的方案先进入 `Experimental`
- 新增顶层目标函数通常属于 `Increment`

## 4. 决定是否开发

根据模板结论决定：
- 进入开发
- 先补文档
- 先补测试
- 先重收敛治理结构
- 暂缓处理

## 5. 开发前确认

开发前必须确认：
- 只做一个目标
- 影响面已明确
- 回滚方式已明确
- 需要的测试已明确
- 需要更新的文档已明确

## 6. 执行开发

按照执行治理进行：
- 先做最小改动
- 避免跨层级扩张
- 保持主线可运行
- 必要时加入开关或降级路径

## 7. 补测试

按照测试治理补齐：
- 单元测试
- 集成测试
- 回归测试
- 验收测试

## 8. 更新文档

按影响范围更新：
- 状态文档
- 路线图
- 阶段任务
- 工程包索引
- 必要时更新治理规范

## 9. 验证与收口

确认：
- 新功能达到验收标准
- 旧功能未被破坏
- 默认路径可回滚
- 文档和状态同步

## 10. 归档或进入下一轮

### 如果是实验
- 归入 `experimental`

### 如果是增量
- 保持在 `increment`
- 等待后续继续推进

### 如果已经过期
- 归入 `archive`

## 11. 一句话流程

> 提需求 → 填模板 → 判层级 → 决定开发 → 执行开发 → 补测试 → 更新文档 → 验证收口 → 归档或继续推进。
