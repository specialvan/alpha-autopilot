# V7 Codex 开发治理规范

## 1. 治理目标

- 保持 `v1/v2` 基线稳定收口。
- 将 V7 功能限定在 Increment 层推进。
- 确保每个 PR 可测试、可回滚、可追溯。
- 将评审文档结论转化为工程门禁与验收证据。

## 2. 分层定义

### 2.1 Baseline

- 范围：`v1/v2` 默认行为路径。
- 允许：缺陷修复、兼容修复、稳定性修复。
- 禁止：V7 新能力默认接入。

### 2.2 Increment（V7 主战场）

- 范围：`PR-AA-26 ~ PR-AA-39`。
- 规则：默认灰度/开关受控，具备回退能力。
- 要求：每次迭代只推进一个清晰目标。

### 2.3 Experimental

- 范围：V7.x 的候选算法、候选提示策略、候选评估器。
- 规则：不得影响默认主链路。

### 2.4 Archive

- 范围：废弃稿、过期决议、历史评审快照。
- 规则：只读，不作为当前开发依据。

## 3. 权威文档优先级

1. 本文档（V7 约束）
2. `claude_review_package/CODEX_DEVELOPMENT_GOVERNANCE.md`
3. `MASTER_ROADMAP.md`
4. `V7_DEVELOPMENT_PLAN_PR_2026_04_30.md`
5. 其他 V7 评审材料

## 4. 需求接入门禁

进入 V7 Increment 必须满足：

- 能映射到 `PR-AA-26 ~ PR-AA-39` 或其明确子任务。
- 不破坏 `v1/v2` 默认接口与默认行为。
- 存在自动化验证路径。
- 存在独立回滚路径。
- 影响面可记录并可审计。

## 5. 退出门禁（可合入候选）

- 受影响测试 100% 通过。
- 新增能力支持 feature flag 关闭。
- 提供回滚清单（<= 5 步）。
- 有离线评估或守护指标证据。
- 文档状态同步完成。

## 6. 回滚优先级

1. 关闭 feature flag
2. 配置回切
3. 模块回退
4. 数据/阈值版本回滚
5. 最后才重做方案

## 7. 一句话治理原则

V7 只在 Increment 层受控生长，所有放量必须先有门禁与回滚。
