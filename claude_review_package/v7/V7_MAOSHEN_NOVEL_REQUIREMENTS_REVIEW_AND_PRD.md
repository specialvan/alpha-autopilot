# alpha-autopilot V7 猫神写作需求评审计划与开发 PR 需求文档

## 1. 文档定位

- 日期：2026-04-30
- 目标版本：V7
- 来源材料：`猫神写作_100条MP3_本地iic模型_GPU转写汇总.md`
- 来源性质：面向网文商业写作的系列经验转写，覆盖题材定位、期待感、爽点、开篇、人物、结构、节奏、文笔、反派、日更、素材库、心理学与长篇续航等主题。
- 上游基础：V1/V2 基线闭环，V3 留存目标函数，V4 人物关系驱动剧情，V5 结构化增强，V6 动态故事世界推演与 AI 小说助手生产主链。
- 输出目的：对源文档逐标题梳理，形成可评审、可拆分、可验收的 V7 开发需求说明 PR 文档。

V7 的核心定位不是“商业写作教练”，也不是把技巧文档做成提示词库，而是建设一套面向 IP 系列化创作的**决断反馈控制系统**。

LLM 的概率性输出本质上是开环系统：如果只让模型根据上下文继续生成，它会在风格、卖点、节奏、人物关系和读者预期上逐渐漂移。传统做法是在关键节点强行人工干预，但这种节点式干预会把故事越修越“变味”；反过来，若每个细节都做风控，又会导致成本不可接受、创作流被打断。因此 V7 要解决的不是“多给几个建议”，而是建立足够全面的量化指标与决断反馈机制，在自由生成与负反馈控制之间取得平衡。

> V7 要把 alpha-autopilot 从“能推荐/能推演故事”升级为“能基于对标小说逆向拆解出的量化指标，对每一次叙事决断进行反馈控制的系统”。

在 V7 中，每次对标小说拆解都不是为了收藏案例，而是为了补全量化标准；每次生成更优质的基准指标，也都是为了补全量化标准。系统最终要做到：每一次剧情推进、人物选择、爽点兑现、情绪拉扯、节奏升降，都能像交易系统一样给出依据、阈值、风险和反馈。

## 2. 评审计划

### 2.1 评审目标

本轮评审需要回答八个问题：

1. 源文档中每个标题对应的写作能力是什么？
2. 这些能力能否被转译为可量化指标、阈值、状态转移或风控条件？
3. 这些能力在 V4/V5/V6 中是否已有抽象或实现？
4. 哪些内容只是已有能力的案例化重复，不应新增模块？
5. 哪些内容与现有抽象存在冲突，需要修正 V1/V2/V3/V4 的基础模型？
6. 哪些内容对 V7 的决断反馈控制极其重要，应作为 P0/P1 进入开发 PR？
7. 哪些内容只应进入对标拆解知识库，用来持续校准指标？
8. 哪些指标可以映射到叙事 K 线、支撑位/阻力位、读者下注量和交易式决断？

### 2.2 评审方法

对每个标题按以下字段评审：

- 标题与核心主张；
- 可抽象的产品能力；
- 可量化指标：状态值、变化率、阈值、波动、成交量代理指标；
- 对应的写作阶段：开书、开篇、章节、卷级、全书、日更、复盘；
- 与 V4/V5/V6 的关系：继承、重复、冲突、缺口；
- 是否需要更改 V1 初始抽象；
- 对叙事决断的作用：开仓、加仓、减仓、止损、止盈、观望、反转确认；
- 优先级：P0/P1/P2/P3；
- 建议落点：指标模型、决断引擎、反馈控制器、后端 API、Workbench UI、对标拆解库、评估器、测试集。

### 2.3 评审分工建议

- 产品/需求评审：确认 V7 是否聚焦“决断反馈控制系统”，避免退化成普通写作助手或技巧提示词库。
- 指标/量化评审：确认每个技巧能否落到可计算指标，无法量化的内容只能进入对标拆解知识库。
- 控制/决策评审：确认决断引擎是否具备负反馈、阈值、止损、反转确认和漂移抑制能力。
- 后端评审：确认 V7 schema 是否兼容 V2 StoryState、V3 retention、V4 relation/pressure、V6 simulation，并能承载 K 线式状态转移。
- 前端评审：确认 Workbench 是否能展示指标 K 线、支撑/阻力阈值、读者下注量、决断理由和反馈闭环。
- 测试评审：确认每个 PR 都有可回放输入、评分解释、阈值命中、反馈修正、降级策略和快照测试。

## 4. V4/V5/V6 阶段对照结论

### 4.0 V7 的系统级修正：从生成系统到反馈控制系统

V4/V5/V6 已经分别补足了人物因果、留存欲望、结构化增强和动态推演，但它们仍然更接近“生成/推荐/推演系统”。V7 的关键修正是：

- 不再把 LLM 输出视为一次性答案，而是视为一根根连续生成的叙事 K 线；
- 不再把对标小说拆解视为写作技巧归纳，而是视为市场历史行情的逆向拆解；
- 不再把评分视为静态打分，而是视为交易前的风控判断；
- 不再把反馈视为人工意见，而是视为下一次决断的负反馈输入；
- 不再把 IP 风味视为抽象风格，而是视为一组可调试、可回测、可迁移的维度参数组合。

K 线的 OHLC 结构天然对应叙事单元状态转移：

- `Open`：该叙事单元进入时的基准状态，例如期待感、爽点债务、冲突压强、人物张力、IP 风味一致度；
- `High`：单元内部达到的最高读者吸引力或情绪冲击；
- `Low`：单元内部的最低风险点或情绪回撤，例如拖沓、跑偏、设定堆叠、人物失真；
- `Close`：单元结束时沉淀下来的读者继续下注意愿，即下一章/下一卷/下一代 IP 的承接状态；
- `Volume`：读者行为数据或其代理值，例如点击、追读、评论、收藏、完读、付费、二创讨论、角色投票，也可以在未上线阶段由对标拆解指标模拟。

阈值对应支撑位与阻力位：

- 支撑位：一个维度不能跌破的最低可接受阈值，例如核心卖点兑现、角色可信度、IP 风味一致度、主线清晰度；
- 阻力位：一个维度需要突破才算完成创新或升级的上沿，例如新爽点、新反差、新冲突强度、新情绪高点；
- 跌破支撑位意味着止损、回滚、减仓或强制修复；
- 突破阻力位意味着确认有效创新，可加仓推进；
- 缩量突破意味着风险较高，需要等待二次确认；
- 放量跌破意味着读者下注撤离，需要立即进入负反馈修正。

因此，V7 的每一次决断都应被视为“一笔有依据的交易”：系统基于对标小说逆向拆解出的配套参数，模拟当前市场行情，判断是否推进、收缩、转向、回滚或加大投入。

### 4.1 与 V4 的关系

V4 已经建立“人物关系 + 性格选择 + 外部压力 -> 剧情自然生成”的因果链。源文档中大量内容都能落到 V4：

- 退婚、羞辱、家暴、资源争夺、时间倒计时，属于外部压力；
- 反派压迫、阶级羞辱、强权退婚，属于地位差与控制/依赖；
- 女神背叛、兄弟背刺、家族压制，属于信任/背叛与情感差；
- 主角隐忍、刚烈、腹黑、挑拨离间，属于性格驱动选择。

重复点：源文档中的很多“打脸、羞辱、压力、反派、关系网”不应另起炉灶，而应增强 V4 的压力类型、关系类型和解释能力。

缺口点：V4 没有充分表达“市场定位、核心卖点、读者情绪需求、商业题材选择”。V4 解决剧情为什么发生，但没有解决“这本书为什么值得读者点开”。

### 4.2 与 V5 的关系

V5 已实现或规划：留存欲望向量、六步情节骨架、情绪滑块、角色功能位、关系图、宏观结构、Prompt 压缩。

重复点：

- “期待感、爽点、悬念、压抑后释放”已与 V5 留存欲望、六步骨架、情绪滑块高度重合；
- “人物功能位、配角功能性、关系图”已与 V5 的角色功能标签和关系图重合；
- “宏观结构、卷级结构、套路循环”与 V5 宏观结构选择器重合。

缺口点：

- V5 的留存欲望向量偏抽象，缺少“卖点契约”这一商业表达；
- V5 的六步骨架偏单元剧情，缺少“循环模板/套娃模板/多级结构”的长篇续航模型；
- V5 没有把开篇前 300 字、黄金三章、标题简介作为可诊断资产；
- V5 没有把“文笔表达”拆成可检查项，如过滤词、画面感、环境交互、一笔多用、节奏分段。

### 4.3 与 V6 的关系

V6 引入动态故事世界推演、多路径模拟、事件注入、角色访谈、群体记忆和生产主链。

重复点：

- “计划-意外构建法”“大高潮逆推法”“故事桩串联法”都可纳入 V6 多路径推演，不需要单独造推演系统；
- “人物关系图、群像、阵营手牌法”可作为 V6 状态图和事件注入策略；
- “角色访谈/人物小传/人物一百问”可复用 V6 的角色访谈能力。

缺口点：

- V6 的推演偏故事世界内部逻辑，缺少商业网文外部市场目标；
- V6 的路径评分应加入 V7 的“卖点契约是否保持”“核心读者需求是否被满足”“开篇/章节钩子是否足够快”；
- V6 的生产主链需要加入“扫榜/拆书/素材库/日更心流”的职业化流程。

## 5. 对 V1 初始抽象必须更改的点

V1/V2 的初始抽象偏“章节推荐系统”：输入 StoryState，输出 recommendation/preview/feedback。V7 需要在不破坏兼容性的前提下，对初始抽象做五类升级，使系统从推荐链路变成带负反馈的决断控制链路。

### 5.1 从 `StoryState` 升级为 `NarrativeMarketState`

V1 的 StoryState 适合描述当前章节上下文，但不足以承载“行情”。V7 需要新增上层 `NarrativeMarketState`，用于表达当前 IP/作品在市场参数空间中的位置。

它至少应包含：

- `project_state`：作品级状态，含平台、题材、读者画像、IP 风味、核心卖点契约；
- `story_state`：当前章节/卷的叙事状态，兼容原 V1/V2 StoryState；
- `benchmark_state`：对标小说逆向拆解出的行情参数；
- `metric_state`：当前维度指标值；
- `kline_state`：按叙事单元聚合的 OHLCV；
- `threshold_state`：支撑位、阻力位、止损线、突破确认线；
- `decision_state`：上一次决断、执行结果、反馈偏差、下一次可用仓位。

### 5.2 从 `StoryState` 升级为 `NovelProjectState`

在 `NarrativeMarketState` 下，V7 仍需要 `NovelProjectState` 承载作品资产：

- 目标平台与题材赛道；
- 书名、简介、卖点契约；
- 核心读者画像与核心情绪需求；
- 黄金三章资产；
- 全书/卷/章多级循环模板；
- 对标拆解样本与基准指标；
- 素材库、拆书资产、写作训练记录；
- 日更计划与任务恢复状态。

V7 不应废弃 StoryState，而应让 StoryState 成为 NovelProjectState 与 NarrativeMarketState 的子结构。

### 5.3 从“推荐候选”升级为“交易式叙事决断”

V1 的输出偏推荐候选。V7 输出必须升级为 `NarrativeDecision`：

- 决断类型：开仓、加仓、减仓、止损、止盈、观望、反转确认、突破追随、回撤修复；
- 决断对象：剧情线、人物关系、爽点兑现、节奏、反派压力、IP 风味、开篇钩子、文笔表达；
- 决断依据：命中的指标、阈值、K 线形态、成交量代理、对标参数；
- 风险等级：P0 致命、P1 严重、P2 可优化；
- 执行动作：删设定、提前危机、补金手指、加倒计时、增加反派压迫、回滚支线、强化卖点兑现等；
- 预期反馈：下一叙事单元应观察哪些指标是否修复。

### 5.4 从“章节级留存”升级为“卖点契约与 IP 风味参数组合的一致性”

V3/V5 已有留存目标，但 V7 需要新增两个核心控制对象：

1. `SellingPointContract`：读者点开这本书时下注的核心预期。
2. `IPFlavorVector`：同一 IP 风味对应的维度参数组合。

V7 要回答的不只是“这一章留不留人”，而是：

- 标题/简介/开头承诺了什么？
- 正文是否持续兑现同一卖点？
- 本次创新是突破阻力位，还是跌破原 IP 风味支撑位？
- 同一 IP 下一代作品是否仍保留核心风味参数？
- 新增参数能推到什么程度，何时会破坏原风味？

这会成为 IP 系列化创作的根本控制指标。每一代作品都在调试配套生产参数：哪些维度可突破、哪些维度必须守住、哪些读者下注信号说明该风味仍有市场。

### 5.5 从“状态输入”升级为“资产化量化基准系统”

V7 需要把下列内容视为量化资产，而非一次性 prompt：

- 榜单拆解样本；
- 对标小说逆向拆解参数；
- 题材定位记录；
- 核心卖点模板；
- 开篇模板；
- 套娃循环模板；
- 人物关系图；
- 反派压力模板；
- 文笔素材库；
- 历史决断记录；
- 决断后反馈数据；
- 基准指标版本与回测记录。

## 7. NQM-V7 指标体系与叙事 K 线采样标准

### 7.1 NQM-V7 四层指标结构

V7 采纳 Claude 评审报告中的 NQM-V7 作为第一版标准指标体系。NQM 不是替代 K 线，而是 K 线 OHLCV 的采样源：每个叙事单元进入、运行、回撤、收盘时，都对 28 维指标进行采样，然后聚合为 Open/High/Low/Close/Volume。

#### Layer P：进程级（角色 × 场景）

| 指标 | 名称 | 控制意义 |
|---|---|---|
| P1 | `char_consistency_index` | 角色行为是否守住人设支撑位 |
| P2 | `voice_drift_score` | 角色声线是否漂移 |
| P3 | `goal_alignment_ratio` | 行动是否对齐当前目标 |
| P4 | `function_type_fidelity` | 角色是否履行功能位 |
| P5 | `goal_urgency_index` | 目标是否有倒计时与失败代价 |
| P6 | `dialogue_identity_coefficient` | 对话是否具有身份差异和潜台词 |
| P7 | `viewpoint_consistency_score` | POV 切换是否合法 |

#### Layer T：张力级（情节单元）

| 指标 | 名称 | 控制意义 |
|---|---|---|
| T1 | `six_step_coverage` | 情节骨架是否完整 |
| T2 | `tension_gradient` | 张力是否递进 |
| T3 | `desire_vector_hit_rate` | 是否命中主导留存欲望 |
| T4 | `hook_density` | 信息钩子是否足够 |
| T5 | `climax_payoff_ratio` | 高潮释放是否匹配前置积累 |
| T6 | `random_reward_density` | 奖励是否具备不可预期性 |
| T7 | `social_validation_score` | 高潮是否有人前认证和见证者反应 |
| T8 | `opening_hook_composite` | 开头综合钩子评分 |
| T9 | `antagonist_pressure_index` | 反派压迫是否足够，是否降智 |
| T10 | `sensory_immersion_score` | 关键场景是否具备感官沉浸 |

#### Layer W：世界一致性（跨章节）

| 指标 | 名称 | 控制意义 |
|---|---|---|
| W1 | `rule_violation_rate` | 是否违反 Story Bible |
| W2 | `info_reveal_velocity` | 信息披露是否过快或过慢 |
| W3 | `foreshadow_fulfillment` | 伏笔是否在有效范围内兑现 |
| W4 | `relationship_causality` | 关系变化是否有因果前事 |
| W5 | `conflict_layer_coverage` | 外部/内部/社会命运冲突是否共振 |
| W6 | `death_emotional_payoff` | 角色退场是否形成情绪回响 |

#### Layer A：平行世界对齐与 IP 风味

| 指标 | 名称 | 控制意义 |
|---|---|---|
| A1 | `path_divergence_score` | 当前路径与最高留存平行路径的偏离 |
| A2 | `character_state_delta` | 角色状态与参照路径的差异 |
| A3 | `event_causality_coherence` | 事件是否能在共享因果图中找到先行事件 |
| A4 | `retention_trajectory_alignment` | 当前路径留存曲线与顶级路径是否同向 |
| A5 | `reversal_quality_score` | 反转是否逻辑自洽且突破预期 |
| A6 | `ip_flavor_corridor_delta` | 当前作品是否仍在 IP 风味廊道内 |

### 7.2 合成评分与默认阈值

默认合成评分：

```text
NQM_V7_composite = Σ(wᵢ × NQMᵢ)

默认权重：
Layer A = 35%
Layer T = 30%
Layer P = 20%
Layer W = 15%
```

默认决断阈值：

- `H = 0.78`：自由生成带。当前指标高于 H 时，降低采样频率，减少干预。
- `L = 0.52`：弹性注入带。当前指标位于 L 与 H 之间时，允许从平行世界参照路径 soft-inject 事件。
- `< L`：硬性干预带。当前指标低于 L 时，进入强约束注入、回滚、止损或人工确认。
- `T8 < 0.60`：开头门禁。首章或黄金三章未通过时，阻断继续生成直到修复或作者 override。

这些默认值不是固定真理，而是 V7 初始基准。后续由 `BenchmarkParameterSet` 与拆书入库管道按平台、题材、IP 风味、目标读者画像重新拟合。

### 7.3 NQM 与 K 线的映射

- `Open`：叙事单元开始时的 28 维 NQM 向量与综合分。
- `High`：单元内局部最高 NQM 综合分，重点关注 T2/T5/T7/A5。
- `Low`：单元内最低 NQM 综合分，重点关注 P1/P3/T4/T9/W1/A6。
- `Close`：单元结束时的 NQM 综合分及下一单元承接状态。
- `Volume`：真实读者行为数据或对标模拟成交量；无真实数据时使用 T4、T5、T7、A4、评论情绪代理。

### 7.4 关键门禁与路由

1. **开头门禁**：`T8 < 0.60` 阻断继续生成，触发毒点检查器。
2. **章末钩子守卫**：章节结尾 300 字内 `T4 = 0`，生成神秘物品/异常事件/灵魂拷问三类建议。
3. **反派降智预警**：`T9 < 0.5` 或 5 章内骤降超过 0.2，触发解释或修复。
4. **情节死锁检测**：连续 3 章 `T2_slope < 0.05` 且 `T4 < 0.2` 且 `P3 < 0.4`，触发 DeadlockRouter。
5. **冲突层缺失**：连续 2 个情节单元 `W5 < 0.67`，建议注入内部冲突或系统性冲突。
6. **IP 风味漂移**：`A6` 偏离廊道超过 2σ，进入风味支撑位风险处理。
7. **反模式黑名单**：POV 污染、对话尴尬、逻辑崩坏、主角木偶、反派降智、读点操作、节奏拖沓、自嗨选题均进入 Anti-Pattern Registry。

### PR-AA-28：NQMSampler 与 NarrativeMetricOHLCV 叙事 K 线模型

- 来源映射：吸收 Claude PR-AA-18、PR-AA-25、PR-AA-26、PR-AA-27、PR-AA-28。

## 9. 主要冲突与处理原则

### 8.1 市场导向 vs 兴趣驱动

源文档中一部分强调市场定位，一部分强调新人先写自己热爱的故事。处理原则：

- V7 不做单一价值判断；
- 新增“商业优先/兴趣优先/折中模式”；
- 对商业模式给出更强的市场定位建议；
- 对兴趣模式只提示风险和受众窄化。

### 8.2 模板化 vs 自然生成

V4 明确反对纯模板化桥段库，而源文档中有大量模板。处理原则：

- 模板不能硬编码为唯一剧情；
- 模板应作为“候选结构/诊断维度/知识库”；
- 最终生成仍要经过 V4 的关系-性格-压力因果解释。

### 8.3 爽文效率 vs 长篇深度

源文档大量强调快节奏、短视频化、爽点密集，但 V6 强调动态世界与角色真实。处理原则：

- 开篇与首卷可提高商业效率；
- 中后期必须引入多级结构、人物关系、反派压力和代价；
- 避免全书只有一级打脸循环。

### 8.4 读者操控语言的伦理边界

源文档中存在“上瘾、拿捏读者、原罪”等表达。处理原则：

- 产品中不使用操控性文案；
- 内部模型可理解“留存机制”，但对用户输出改为“阅读吸引力、期待感、情绪满足、继续阅读意愿”；
- 不引导欺诈、低俗或违法内容。

## 10. 验收建议

每个 V7 PR 至少需要：

- schema 单元测试；
- 指标计算快照测试；
- K 线 OHLCV 聚合测试；
- 阈值命中与支撑/阻力判断测试；
- 决断输出测试：开仓、加仓、减仓、止损、止盈、观望、反转确认；
- 反馈回写测试：上次决断结果如何影响下一次决断；
- 与旧 StoryState 的兼容测试；
- V2 Workbench 序列化测试；
- 至少 3 个中文小说样例输入；
- 至少 1 个“重复/冲突/低质量”负例；
- 至少 1 个“跌破 IP 风味支撑位”的系列化负例；
- 至少 1 个“突破阻力位但缩量，需要二次确认”的创新负例；
- 降级策略：未提供市场/卖点/对标参数时，不阻塞现有 V2/V6 主链，但必须标记为低置信度开环输出。

## 11. 总结

V7 最重要的不是把 100 条写作技巧原样搬进系统，也不是把 alpha-autopilot 做成普通商业写作教练，而是建立一套能把 LLM 开环输出闭合起来的决断反馈控制系统。

V7 的核心判断如下：

1. 每次对标小说拆解都是为了补全量化标准；
2. 每次生成更优质的基准指标都是为了补全量化标准；
3. LLM 概率性输出如果缺少负反馈，必然在卖点、节奏、人物和 IP 风味上漂移；
4. 单靠节点式人工干预会慢慢变味，单靠全细节风控又不现实；
5. 足够全面的量化指标与决断系统，是自由生成和反馈控制之间的平衡器；
6. K 线 OHLCV 可以表达叙事单元的状态转移；
7. 支撑位/阻力位可以表达指标阈值；
8. 读者行为数据或对标模拟数据可以表达成交量；
9. 每一次叙事决断都应像一笔有依据的交易；
10. IP 系列化创作的根本，是持续调试同一 IP 风味对应的维度参数组合，判断每一代作品能把哪些参数推到什么程度。

因此，V7 应被定义为：

> 面向 IP 系列化商业网文生产的“对标拆解量化指标 + 叙事 K 线模拟 + 支撑/阻力阈值 + 读者下注反馈 + 决断控制”的闭环反馈系统。

在这个定义下，市场定位、核心卖点、开篇钩子、情绪曲线、循环续航、反派压力、节奏信息、文笔表达都不再是孤立功能，而是参与交易判定的指标维度。系统最终输出的也不只是建议，而是带依据、带阈值、带风险、带反馈目标的叙事决断。
