# 实验层说明

本目录用于放置实验性文档和探索性材料。实验层的目标不是直接产出主线结论，而是先验证方法、口径、结构或评估方式是否可用。

## 用途

- 验证新的方案、流程、拆分方式或评估器
- 试验新的数据结构、提示词策略或分析方法
- 记录尚未稳定、尚未形成统一门禁的探索结果

## 门禁

只有在满足下列情况时，材料才应进入实验层：

- 方案还不明确，且需要先做探索验证
- 指标或验收口径还不稳定
- 预期需要多轮试验或快速回滚
- 现有主线或增量层不适合直接承载该变更

以下内容不应直接进入实验层替代正式结论：

- 已明确可落地的主线修复
- 已满足增量层门禁的新功能
- 需要稳定收口并可持续交付的正式文档

## 与 `mainline` / `increment` 的关系

- `mainline` 是当前稳定主线，只接收已经确认的结论、修复和约束
- `increment` 承接可独立推进、可回滚、可评估的增量需求
- `experimental` 只负责前置探索，不直接改变主线默认行为
- 实验结果只有在结论清晰、风险可控、边界明确后，才考虑迁移到 `increment`，再进一步进入 `mainline`

## 执行规则

- 实验材料应与主线文档分开管理
- 每次实验都应明确目标、假设、观察点和退出条件
- 结论为负面或不稳定时，优先保留为实验记录，不要包装成正式规范
- 若实验内容已经稳定，需及时升级到对应层级并补齐治理文档
