## 1. 打回问题（按严重度）

### P0-1：目标描述偏概念化，缺少可验证的最小通过标准

现状：

- 文档中大量使用“自然长出来”“不是灵感瞎想”等价值判断语句。
- 这些语句可以指导方向，但不能直接转化为工程验收标准。

风险：

- 代码实现会出现“各自理解”，导致评审争议和回归标准漂移。
- 测试只能验证“有输出”，无法验证“是否满足 V4 核心目标”。

修订要求：

1. 把 V4 首发验收口径收敛成最小可测集合：
   - 输入关系/性格/压力后，至少输出 2 个剧情候选。
   - 每个候选必须附带可解释字段（触发关系、触发性格、触发压力、选择理由）。
   - 关闭 V4 后必须回退到 V3 路径且不报错。
2. 把“自然性”拆成代理指标（例如：关系张力、压力强度、候选分歧度、模板风险）。

### P0-2：V4 与 V3 的排序契约不够明确

现状：

- 文档写明“V4 产候选，V3 做留存排序”，但没有冻结字段契约和冲突规则。

风险：

- 可能出现 V4 本地排序与 V3 排序重复或相互覆盖。
- 生产行为不稳定，难以回放排查。

修订要求：

1. 固化桥接载荷：
   - `retention_sort_key`
   - `candidate_count`
   - `selected_candidate_id`
   - `qc_summary`
2. 固化优先级：
   - V4 只负责候选生成与基础评分。
   - 最终选择权由 V3 留存排序决定。

### P1-1：回滚策略只有文字描述，缺少可执行开关

现状：

- 文档要求“可关闭/可降级”，但接口与代码层没有强制开关契约。

风险：

- 回滚依赖人工改代码，不满足阶段治理要求。

修订要求：

1. 增加 `v4_enabled` 显式开关（context 或配置）。
2. 开关关闭时返回结构化降级响应，不抛异常，不影响主链路。

### P1-2：测试计划仍偏叙述，缺少“需求->测试文件”映射

现状：

- 测试计划覆盖面较全，但未给出清晰映射矩阵。

风险：

- 难以判定“某个需求是否已被测试覆盖”。

修订要求：

1. 增加最小映射：
   - 关系模型 -> `tests/test_alpha_autopilot_v4_modules.py`
   - V4 API 契约 -> `backend/tests/test_narrative_v4_api.py`
   - V4 关闭降级 -> 同上
2. 纳入分层测试入口，作为 V4 阶段门禁。

## 2. 修订后可执行口径（本版批准范围）

本轮只批准以下 V4 首发范围：

1. 关系/性格/压力三层模型及分析器。
2. 多候选剧情生成（>=2，条件不足时可降级但要解释）。
3. V4->V3 桥接载荷（含候选数、选中候选、排序键、QC摘要）。
4. `v4_enabled` 回滚开关。
5. 单元+API+分层门禁测试可跑通。

以下内容留待后续迭代：

- 大规模题材扩展
- 自动学习人格向量
- 多轮标注闭环
- 复杂桥段聚类与自动重写
