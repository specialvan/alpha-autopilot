# 文档约定

更新时间：2026-05-08

## 事实优先级

文档解释冲突时，按下列优先级取舍：

1. 当前代码实现
2. 当前前端消费契约
3. 仓库内现有 API 文档
4. 历史阶段文档

## 标记规范

- `代码定义`：字段、枚举、默认值、约束可直接在当前源码中找到。
- `前端已消费`：字段已出现在 `ui-react/src/api.ts` 或相关前端控制器中。
- `[推断]`：代码没有显式注释，但可从调用链、回退分支或命名结构中推出。
- `待确认`：代码中没有足够信息，或当前实现与文档意图可能不一致。

## 层次命名

- `Baseline`：当前稳定主链，优先解释接口与输入输出。
- `Increment`：增强层，优先解释如何接入 Baseline，而不是算法内部推导。
- `Experimental`：实验链路，必须单独标注，不应默认视作主线。

## 契约模板

每个接口或对象，尽量按以下模板记录：

- 名称
- 所在文件路径
- 功能说明
- 输入参数
- 输出结果
- 前置条件
- 错误分支
- 依赖关系
- 稳定性说明

## 字段说明约定

- `必填`：Pydantic 无默认值，或 route 要求 path/body/query 必须传入。
- `默认值`：Pydantic 默认值、Query 默认值、代码 fallback 值。
- `后端未限制`：前端使用了更窄枚举，但后端源码本身只定义为 `str` 或 `dict[str, Any]`。
- `嵌入预览`：对象不对应独立 route，而是嵌入另一个响应中返回。

## 状态流转约定

如果对象具备状态机含义，应至少说明：

- 入口状态
- 迁移条件
- 成功输出
- 失败/降级输出
- 是否需要人工确认

## 本目录当前重点

当前阶段最需要固定的，不是所有模块说明，而是：

- 推荐链路
- 任务调度入口
- 策略选择
- 执行反馈
- 输入数据 / 模型规则 / 排序结果 / 最终输出
- 在线 / 离线流程分界
- 异常兜底
- 配置项
