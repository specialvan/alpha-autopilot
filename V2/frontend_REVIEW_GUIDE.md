# 前端 Codex 评审说明

## 评审目标

验证前端工作台是否满足小说章节智能推荐引擎的工程交付要求。

## 治理定位

- `Dashboard` 属于 Baseline 的展示层
- `V2 Workbench` 属于 Increment 的决策层
- 评审时不得把两者混成一个产品层级

## 重点检查项

1. 信息结构是否清晰
2. 视觉层次是否合理
3. 是否与后端原型术语一致
4. 是否保留真实接口接入空间
5. 是否方便后续组件化拆分
6. 是否适合展示版本、日志、反馈和风险信号

## 评审关注点

- 页面是否能快速读懂当前模型状态
- KPI 是否足够明确
- 推荐结果是否具备解释性
- 日志和版本区是否便于复盘
- 文档是否能支撑后续工程交付

## 交付边界

本次前端只做工作台原型与交付文档，不强行接入真实服务，以便先稳定规范和信息结构。

## 后续演进

- 接入真实 API
- 把静态卡片改为动态数据
- 引入前端状态管理
- 拆分为可维护组件
- 与后端形成统一发布节奏
